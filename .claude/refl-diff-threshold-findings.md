# 反射/繞射關閉門檻 — 最終建議

> 量測日期：2026-09-21 · Intel UHD 770 內顯 · demo 平面圖（30.0 × 22.4 m）
> 判準：**跨越等高線（−45 / −55 / −65 dBm）的格點比例 ≤ 10%**
> （= 一般人看熱圖讀「綠/黃/橘/紅」四段語意時，有多少比例的區域語意跑掉）
> 紅色 clamp 區內部變化不計（畫面沒變就是沒變）

---

## 建議：`AP數 / 牆線段數 ≥ 0.25` 時關閉反射繞射

```js
const segCount = scenario.walls.length   // 展開後的線段，不是牆物件數
const apPerSeg = scenario.aps.length / Math.max(1, segCount)
const forceAggregated = apPerSeg >= 0.25
```

**216 組驗證（4 種牆密度 × 6 種 AP 數 × 3 種分佈 × 3 個 seed）：**

| | 值 |
|---|---|
| 觸發比例 | 50% 的場景 |
| 觸發時最差語意差異 | **7.56%** ✅ |
| 觸發時超過 10% 的組數 | **0 / 108** ✅ |
| 觸發時最差 −67 覆蓋翻轉 | 0.64% |

加上 `牆×AP 積` 的複合條件測過，**沒有變更好**，所以不需要 —— 單一條件就夠。

## 為什麼是 `AP / 牆` 而不是 `AP × 牆`

實測發現會「看得出差異」的場景全部是**牆多但 AP 少**：

| 場景 | 語意差異 | apPerSeg |
|---|---|---|
| 243 seg / 10 AP | 11.94% ❌ | 0.04 |
| 243 seg / 20 AP | 12.40% ❌ | 0.08 |
| 243 seg / 30 AP | 13.47% ❌ | 0.12 |
| 193 seg / 10 AP | 12.51% ❌ | 0.05 |
| 193 seg / 20 AP | 11.44% ❌ | 0.10 |

這些的 `牆×AP` 積分別是 2430 / 4860 / 7290 / 1930 / 3860 —— **有大有小，
用積無法乾淨切開**（T=8000 時仍有 1 組漏網）。
但它們的 `AP/牆` 全部 < 0.13，用比值一刀切乾淨。

物理上說得通：反射繞射的價值是補「直射打不到的角落」。
AP 相對牆夠多時，每個角落都有 AP 直射得到，陰影被填滿，反射訊號被 max 蓋過去；
AP 相對牆太少時，反射繞射是唯一照亮死角的機制，關掉會讓整片區域的語意跑掉。

## 仍要注意的事

1. **AP 集中一區（cluster）的場景** 語意差異會偏高（最差 7.45%），
   但仍在 10% 內，規則安全。
2. **深陰影區**（≤ −75 dBm，clamp 成同色）的變化在此判準下完全隱形。
   這是依設計（以畫面為主），但若日後要做「訊號死角報告」之類的功能，
   不能沿用這個判準。
3. **建議在 UI 明示已簡化** —— `setSimplifiedLargeScene` 已有這個管道。
   不是因為畫質不能接受，而是讓專業使用者知道自己看的是簡化版。
4. 拖曳中維持關閉（現有 `lodActive` 路徑）—— 不用改。

## 附註：量測方法

- 時間：warm-up 各一次丟棄 → 完整/簡化交錯 → 5 次中位數，離散度 ±3%。
- 畫質：走 `sampleFieldGLAsync` 直接取 rssi 陣列，不經畫面像素讀回。
- 等高線分段取自 `heatmapGL.js` 實際繪製的 anchors（`modes.js` RSSI_ANCHORS）。
- 擴充牆為 3-8 m 的室內隔間（75% 輕隔間 4dB / 25% 混凝土 12dB），
  用 `startX/startY/endX/endY` schema，已驗證 unique segment 數。

### 過程中修正的錯誤（保留供參考）

1. **harness bug**：最初的合成牆用了 `points/start/end` 欄位，
   但 `buildScenario` 讀 `startX/startY/endX/endY` —— 導致「加密的牆」
   其實是同一面牆的重複複本。修正前某指標相關性看似 0.81，修正後掉到 0.47。
2. **判準換過三次**：平均 dB 誤差（不可比，同樣 1 dB 在不同訊號強度的
   視覺後果差 3 倍）→ CIEDE2000 色差（太嚴格，把「深綠變淺綠」也算進去）
   → **跨等高線比例**（對應一般人實際的讀圖方式）。

### 順帶發現的疑似 bug

`modes.js` 的 RSSI anchors 在 **−55 和 −65 是同一個橘色 `255,128,13`**，
造成這 10 dB 區間在畫面上完全同色（CIEDE2000 ΔE = 0）。
剛好涵蓋 −67 決策線上方最關鍵的區間。不確定是刻意設計還是筆誤。
